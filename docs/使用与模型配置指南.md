# Podcast Radar 使用与模型配置指南

这份指南面向两类使用者：

- 只想安装应用、发现节目并完成转录的普通用户。
- 希望使用自己的 API、替换本地转录模型，或为其他云端 ASR 编写适配器的开发者。

当前版本遵循“本地优先”的原则：默认先用本机 `faster-whisper` 转录；需要更高速度时，可以填写自己的阿里云百炼 API Key，启用并发云端转录。API Key、浏览器 Cookie、下载音频、转录稿和个人资料库都只保存在本机。

> 当前内置的云端服务商只有阿里云百炼（DashScope）。OpenAI、Deepgram、自建 Whisper HTTP 服务等不能直接把地址填进设置页，需要按本文的“接入其他 ASR API”一节增加适配器。

## 1. 先认识四个模型

| 功能 | 当前默认模型 | 是否必须联网 | 在哪里配置 |
| --- | --- | --- | --- |
| 音频转文字 | `faster-whisper medium` | 首次下载模型需要，之后可离线 | 默认内置；源码用户可替换 |
| 极速云端转录 | 阿里云百炼 `qwen3-asr-flash` | 是 | 设置页填写 `DASHSCOPE_API_KEY` |
| 中文全文翻译与研究整理 | 阿里云百炼 `qwen-plus` | 是 | 与云端转录共用同一个 Key |
| 播放中文译文 | 本机 Qwen3-TTS | 模型准备好后可离线 | 设置页“本地朗读 TTS” |

`faster-whisper` 负责把播客声音变成文字；Qwen3-TTS 负责把中文译文朗读出来。两者用途不同。

## 2. 安装和第一次启动

### 2.1 直接安装 macOS 应用

1. 从 [GitHub Releases](https://github.com/qihaoshen857-ship-it/Podcast-Radar/releases/latest) 下载最新的 `.dmg`。
2. 打开 `.dmg`，把 `Podcast Radar` 拖入“应用程序”。
3. 第一次打开时，如果 macOS 阻止运行，进入“系统设置 → 隐私与安全性”，确认打开。
4. 应用会继续沿用历史数据目录：

   ```text
   ~/Library/Application Support/ResearchPodcastRadar
   ```

本地 Whisper 模型通常会在第一次转录时下载，因此第一次需要联网并耐心等待。模型下载完成后，本地转录可以离线使用。

### 2.2 从源码运行

克隆仓库后，双击：

```text
run_macos.command
```

首次运行会在项目目录创建独立运行环境，后续直接启动。也可以在终端执行：

```bash
./run_macos.sh
```

不需要修改系统 Python，也不需要管理员密码。更完整的 macOS 安装和排障说明见 [README_MAC.md](../README_MAC.md)。

## 3. 最常用的操作流程

### 3.1 从雷达里选择一条节目

1. 打开“今日雷达”，按 `综合`、`AI`、`天气农业` 或 `养生` 刷新节目。
2. 点击卡片主体查看标题、简介、来源和发布时间。
3. 点击卡片右侧的 `选择`。
4. 点击 `转录整理选中`。
5. 程序会下载当前节目的真实音频，并按设置页选定的方式转录。
6. 完成后进入 `资料库` 或 `阅读` 查看结果。

如果节目提供官方 Transcript，程序会先核对文稿中的标题与当前节目是否一致。标题错期、无法验证或缺少同期文稿时，会转而下载当前音频并进行 ASR，避免出现标题和正文对不上。

### 3.2 转录电脑里已有的音频或视频

1. 进入转录页面。
2. 点击 `选择文件`。
3. 选择 `mp3`、`m4a`、`wav` 或 `mp4` 文件。
4. 点击 `开始转录`。
5. 转录结果会保存为与媒体文件同名的 `.txt`。

如果同名 `.txt` 已经存在，程序会把它当作现有结果复用。需要重做时，请先备份并移走旧的 `.txt` 与同名 `.segments` 断点目录。

### 3.3 添加 YouTube 或小宇宙链接

1. 在首页展开 `手动链接`。
2. 粘贴单集、频道、播放列表或小宇宙页面链接。
3. 点击 `读取`。
4. 选择节目后下载或转录。

YouTube 提示机器人校验时，先在 Chrome 中正常登录 YouTube，再在应用设置中把“浏览器登录态”设为 `auto` 或 `chrome`。不要把导出的 `cookies.txt` 发给别人，也不要提交到 GitHub。

### 3.4 阅读中文译文和播放译文

1. 在阅读页打开英文转录稿。
2. 点击 `看译文`，程序会用 `qwen-plus` 分段翻译完整正文并缓存。
3. 点击 `播放译文`，程序会调用本机 Qwen3-TTS 生成连续音频。

生成中文译文需要 `DASHSCOPE_API_KEY`。播放已经生成的译文使用本地 TTS，模型准备好后不需要调用云端语音服务。

## 4. 三种转录方案怎么选

### 方案 A：本地优先，推荐日常使用

在“设置 → 语音转录”中选择：

```text
本地优先
```

特点：

- 默认使用本机 `faster-whisper medium`。
- 音频内容不需要发送给云端。
- 不填写 API Key 也能完成音频转文字。
- 第一次需要下载本地模型；长播客主要受电脑 CPU 性能影响。
- 如果已经填写 DashScope Key，本地 Whisper 失败时会调用阿里云 ASR 补齐。

默认参数建议保持：

```text
目标切分时长：120 秒
最大切分时长：180 秒
云端并发数：4
```

本地 Whisper 当前逐片处理，“云端并发数”不会加速本地模式。

### 方案 B：极速云端，适合长播客

在设置页填写自己的 `DASHSCOPE_API_KEY`，选择：

```text
极速云端
```

程序会：

1. 在本机把长音频切成不超过 180 秒的小片段。
2. 默认以 4 路并发调用 `qwen3-asr-flash`。
3. 按原始顺序合并结果并去除切片重叠文本。
4. 每完成一片就保存断点；重试时只补缺失片段。
5. 云端个别片段失败时，用本地 Whisper 补齐。

并发数建议：

| 情况 | 建议值 |
| --- | ---: |
| 第一次测试、API 限流较严 | 2 |
| 普通长播客 | 4 |
| 账号配额充足、网络稳定 | 6–8 |

程序实际并发上限为 8。更高的数字不会继续提高并发，还可能增加限流和重试。

### 方案 C：只使用自己的本地模型

保持“本地优先”，不要填写 API Key。这样本地失败时程序会明确报错，不会把音频发往云端。

公开版设置页暂时没有“选择本地 ASR 模型目录”的输入框。源码用户可以按照第 6 节替换模型；直接安装 `.dmg` 的用户建议先使用内置 `medium`。

## 5. 填写自己的阿里云百炼 API Key

### 5.1 在应用里填写

1. 登录阿里云百炼控制台，创建或复制自己的 DashScope API Key。
2. 打开 Podcast Radar 的 `设置`。
3. 在 `DASHSCOPE_API_KEY（可选）` 中粘贴 Key。
4. 选择 `本地优先` 或 `极速云端`。
5. 点击 `保存设置`。

这个 Key 同时用于：

- `qwen3-asr-flash` 云端转录。
- `qwen-plus` 中文全文翻译。
- `qwen-plus` 中文研究整理、卡片标题和简介翻译。

### 5.2 从源码配置

复制示例文件：

```bash
cp .env.example .env
```

编辑 `.env`：

```dotenv
DASHSCOPE_API_KEY=你的真实Key
```

`.env` 已被 `.gitignore` 排除。提交前仍建议运行：

```bash
git status --short
git diff --cached
```

确认没有 Key、Cookie、下载音频或个人资料库进入暂存区。

### 5.3 Key 保存在哪里

- 源码运行：项目根目录的 `.env`。
- 安装版应用：`~/Library/Application Support/ResearchPodcastRadar/.env`。

当前 Key 以本机纯文本 `.env` 保存，不会由程序上传到 GitHub。请保护好 macOS 登录账户和备份文件，不要在 Issues、截图、日志或聊天中粘贴完整 Key。怀疑泄露时应立刻在阿里云控制台删除旧 Key 并创建新 Key。

### 5.4 验证配置

源码用户可以双击：

```text
check_system.command
```

也可以运行：

```bash
./check_system.sh
```

检查项包括本地依赖、DashScope Key、设置文件和 Chrome。建议先用 1–3 分钟的音频测试，再处理一两个小时的节目。

## 6. 绑定自己的本地 Whisper 模型

### 6.1 当前支持的模型格式

Podcast Radar 使用 `faster-whisper`，底层模型格式是 CTranslate2。`WhisperModel(...)` 接受：

- 模型名称，例如 `tiny`、`base`、`small`、`medium`、`large-v3`。
- 本地 CTranslate2 模型目录的绝对路径。

普通 Transformers/PyTorch Whisper 目录不能直接使用。自备目录通常应包含 `model.bin`、`config.json`、tokenizer 等 CTranslate2 文件。

### 6.2 修改本地模型

打开 [app/transcription.py](../app/transcription.py)，修改文件顶部的三个常量：

```python
LOCAL_ASR_MODEL = "medium"
LOCAL_ASR_DEVICE = "cpu"
LOCAL_ASR_COMPUTE_TYPE = "int8"
```

使用其他公开模型名称：

```python
LOCAL_ASR_MODEL = "large-v3"
LOCAL_ASR_DEVICE = "cpu"
LOCAL_ASR_COMPUTE_TYPE = "int8"
```

使用已经下载好的本地 CTranslate2 模型：

```python
LOCAL_ASR_MODEL = "/absolute/path/to/your/ctranslate2-whisper-model"
LOCAL_ASR_DEVICE = "cpu"
LOCAL_ASR_COMPUTE_TYPE = "int8"
```

路径请使用真实绝对路径，不要把个人电脑路径提交到公共仓库。

### 6.3 设备和精度建议

| 设备 | `device` | `compute_type` | 说明 |
| --- | --- | --- | --- |
| Intel Mac / Apple Silicon Mac | `cpu` | `int8` | 当前最稳妥的默认组合 |
| NVIDIA CUDA 电脑 | `cuda` | `float16` 或 `int8_float16` | 需要匹配的 CUDA、cuDNN 和 CTranslate2 环境 |

macOS 上不要填写 `mps`；当前 `faster-whisper`/CTranslate2 路径没有使用 PyTorch MPS。

模型越大，通常准确率越高，同时需要更多内存和时间。第一次建议先用短音频比较 `small`、`medium` 和目标模型，确认中英文、人名、公司名的表现后再批量处理。

### 6.4 启动和验证

修改后重新启动应用，选择“本地优先”，转录一段短音频。日志中应该出现：

```text
正在加载本地 faster-whisper 模型：你的模型名或路径
```

更换模型后，片段缓存的模型标识也会变化，程序会为新模型重建对应断点。运行测试：

```bash
.runtime/bin/python -m pytest tests/test_transcription_strategy.py
```

如果要把修改后的版本打成 `.app`：

```bash
./build_macos_app.command
```

模型权重默认不会打进应用包。分发给别人时，可以让应用首次联网下载模型；如果要离线分发，需要另行处理模型许可证、体积和本地路径，不能直接把个人 Hugging Face 缓存整体提交到仓库。

## 7. 接入其他 ASR API 或自建转录服务

当前设置页只识别 `DASHSCOPE_API_KEY`。如果要使用 OpenAI、Deepgram、自建 Whisper、局域网 GPU 服务或其他 API，需要增加一个云端适配器。

现有并发、断点和顺序合并逻辑已经集中在 [app/transcription.py](../app/transcription.py)。最小接入点是：

```python
def transcribe_segment(
    chunk_path: Path,
    api_key: str,
    segment_index: int = 1,
    segment_total: int = 1,
    report: ProgressCallback | None = None,
) -> str:
    # 1. 把 chunk_path 指向的 WAV 发送给你的服务
    # 2. 检查 HTTP 状态和服务端错误
    # 3. 从响应中取出纯转录文本
    # 4. 返回非空字符串
    return post_text_process(text)
```

适配器应遵守以下约定：

1. 输入是本地切好的 16 kHz 单声道 WAV。
2. 单片目标时长默认 120 秒，最大 180 秒，并受 10 MB 限制。
3. 成功时返回当前片段的纯文本，不要返回 Markdown、时间戳 JSON 或解释文字。
4. 失败时抛出 `TranscriptionError`，不要用空字符串伪装成功。
5. 保留 `report(...)` 的开始、完成和重试进度，界面才能正确显示。
6. 不要在源代码中写死 Key；为新服务增加独立环境变量，例如 `YOUR_PROVIDER_API_KEY`。
7. 更新 `build_segment_cache_metadata()` 中的云端模型标识，避免不同模型错误复用旧断点。
8. 在 `tests/test_transcription_strategy.py` 增加成功、限流、部分失败、本地补齐和断点恢复测试。

自建 HTTP 服务推荐提供一个简单、稳定的接口：

```text
POST /v1/audio/transcriptions
Authorization: Bearer <token>
Content-Type: multipart/form-data

file=<wav>
model=<model-name>
```

响应至少包含：

```json
{"text": "当前片段的转录文本"}
```

如果服务兼容 OpenAI 的音频转录格式，也仍需在 Podcast Radar 中写一层请求适配，因为当前界面没有 `BASE_URL`、模型名和厂商类型字段。

## 8. 配置本地 Qwen3-TTS

这一节只影响“播放译文”，不会改变音频转录。

打开“设置 → 本地朗读 TTS”，可以填写：

- `Qwen3-TTS Python`：安装了 Qwen3-TTS 的 Python 可执行文件。
- `模型`：Hugging Face 模型名或本地模型路径。
- `说话人`、`语种`、`控制指令`。
- `单次朗读上限（字）`。

默认 Python 路径：

```text
~/qwen3_tts_local/.venv/bin/python
```

默认模型：

```text
Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice
```

如果使用本地模型目录，请在“模型”中填写绝对路径，并确保上面的 Python 环境已经安装对应 Qwen3-TTS 依赖。

## 9. 数据、隐私和备份

安装版的主要本地数据位于：

```text
~/Library/Application Support/ResearchPodcastRadar
```

其中可能包含：

- `.env`：API Key。
- `settings.json`：应用设置。
- `downloads/`：正式下载的音频和转录。
- `.cache/research/`：临时音频、研究稿、中文译文和 TTS 音频。
- `research_library.json`：资料库索引和原链接。
- 自动导出的浏览器 Cookie 文件。

备份资料时，可以备份整个目录；对外分享或上传问题样本时，请先移除 `.env`、Cookie 和可能含个人信息的资料库。仓库的便携包导出脚本会主动排除这些文件。

## 10. 常见问题

### 本地转录一直停在“加载模型”

第一次通常在下载模型。确认网络可以访问模型下载源，并给终端或应用保留足够时间。若模型已经在本地，请按第 6 节绑定 CTranslate2 目录。

### 长播客转录太慢

有 DashScope Key 时选择“极速云端”，先用 4 路并发测试。完全离线时可以换用 `small`，速度会提高，准确率可能下降。

### 云端提示限流或超时

把并发数从 4 降到 2，稍后重试。成功片段已有断点，不会全部重来。

### 填了 Key 但仍然使用本地 Whisper

确认转录模式是否选择了“极速云端”。“本地优先”只有在本地失败时才调用云端。

### 转录标题和内容对不上

先核对来源链接、发布时间和节目标题。删除或移走错误的同名 `.txt` 后重新整理；程序会重新核对官方 Transcript，无法确认时改走当前音频 ASR。

### 中文译文无法生成

中文全文翻译使用 `qwen-plus`，需要有效的 DashScope Key、联网和可用额度。纯本地 Whisper 只能生成原语言转录。

### YouTube 无法下载

先升级到最新版本，再确认 Chrome 已登录 YouTube，并在设置中选择 `auto` 或 `chrome`。仍失败时运行 `check_system.command` 查看依赖和登录态。

## 11. 提交问题时请带上这些信息

在 [GitHub Issues](https://github.com/qihaoshen857-ship-it/Podcast-Radar/issues) 提交问题时，建议提供：

- Podcast Radar 版本号和 macOS 版本。
- 使用“本地优先”还是“极速云端”。
- 模型名称、`device` 和 `compute_type`，不要提供模型私有下载凭证。
- 一小段已经脱敏的转录日志。
- 可公开访问的节目链接，或可复现的短音频。
- 是否能用 `check_system.command` 通过检查。

请始终遮住 API Key、Cookie、私人下载路径和未公开音频。
